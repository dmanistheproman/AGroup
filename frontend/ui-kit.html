SHARED PARTS / INTERFACE

Shared components.

Every role's pages are built from these parts, so a status, a list or a form looks and behaves the same everywhere. They live in js/records.js and js/ui.js; each section names the function to call. Live data is used where it is public; examples are marked.

Status and historyList pageProject cards Category pickerPeriod and chartUpload RatingFormRecord page

Status badge, reason dialog and history (S-04)

AGroupRecords.statusBadge(status), confirmWithReason({title}), historyTimeline(entries)

List page (S-05)

AGroupUI.toolbar, table, pager, listPage, state('loading' | 'empty' | 'error'). Live: active categories, five per page.

Project card and image gallery (S-08)

AGroupUI.projectCard(project), imageGallery(images). Live: the first published projects. A missing image falls back to a placeholder.

Category picker (S-10)

AGroupUI.loadCategories() then categoryPicker(categories, {multiple}). Only active categories are offered.

Period selector and trend chart (S-06)

AGroupUI.periodSelector(), periodQuery(form), trendChart(rows, series) on GET /api/reports/activity.

Upload widget (S-03)

AGroupUI.uploadWidget({kind}), checkFiles(input), send(url, formData, onProgress). Files are checked here with the server's rules; nothing is uploaded on this page.

Rating (S-11)

AGroupUI.ratingInput(name), ratingDisplay(average, count), ratingForm()

Form view (S-12)

AGroupUI.formView.submit(form, method, url, body) shows field errors from the server ({error, field}), a busy button and a success message. Example only: this form is not sent.

Record page (S-20)

AGroupUI.recordPage({eyebrow, title, status, details, actions, sections}) with the message thread and notes from records.js. Example record.
